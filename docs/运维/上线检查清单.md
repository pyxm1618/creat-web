# 上线检查清单

这份清单区分两件事：**仓库里已经做完的控制**，和**必须有真实外部资源才能完成的部署事实**。

**CI 全绿不等于可以上线。**

## 上线前必须有的外部资源

每一项都记下真实的负责人和环境。**绝不要把任何密钥粘进这份文档。**

- [ ] 真实的 staging 域名和 Vercel 项目，与生产隔离。
- [ ] 真实的 staging PostgreSQL，具备备份/PITR 能力且留存策略已确认。
- [ ] 评审过的法律主体身份、司法管辖区、支持邮箱，以及隐私/条款/使用规范/退款/账号删除的正文。
- [ ] 开启 Google 登录时：Google OAuth staging 客户端，来源和回调配置精确。
- [ ] 开启邮件时：Resend staging API key、已验证的发件人/域名和支持邮箱。
- [ ] 开启交易时：Waffo staging/test 商户、店铺、商品/价格、私钥和 webhook 验签材料。
- [ ] Cloudflare Turnstile staging widget/site key 和 secret，hostname 与 staging 一致。
- [ ] 开启分析时：GA4 和/或 Clarity 的 staging 目的地，且做过同意/隐私复核。
- [ ] 一个真实的告警接收方/on-call 渠道，接上结构化的 `operational_alert` 事件。
- [ ] 生产 SEO 上线时：Search Console 资源/域名验证。**不要提交草稿/staging URL。**
- [ ] 开启 IndexNow 时：生产的 IndexNow 归属密钥。**不要拿 staging URL 当搜索提交证据。**
- [ ] 每个对外宣称支持的语言都有**人工审校过**的翻译。**不要把英文机器复制一份来凑语言路由。**

## 部署配置门禁

- [ ] `VERCEL_ENV=preview` 映射到 `APP_ENV=staging`；Vercel 上拒绝 `APP_ENV=test`。
- [ ] `APP_ORIGIN` 是精确的 HTTPS staging 来源。
- [ ] 密钥按用途隔离：登录、cron、数据库、Waffo、Turnstile、留存加密和服务商凭据**互不复用**。
- [ ] Turnstile 用真实 staging 密钥；Cloudflare 的测试密钥会被 staging 运行时拒绝。
- [ ] 没有测试邮箱传输；开启 staging 邮件时用的是 Resend。
- [ ] Waffo 合约验证标志**只在**商户/店铺/webhook 资源都验证过之后才设置（见 [Waffo 合约与验收](../参考/waffo-合约与验收.md)）。
- [ ] 除非批准的目的地 ID 和同意政策都配好了，否则分析保持关闭。
- [ ] 配了 IndexNow 的话：`INDEXNOW_KEY` 通过格式门禁，`CRON_SECRET` 保护内部提交端点，**公开的 IndexNow 密钥不得复用为内部鉴权**。

## 数据库与恢复演练

- [ ] 对隔离的 staging 数据库跑迁移。
- [ ] 确认 `/api/health/ready` 返回 `ready` 且不泄露连接细节。
- [ ] 做一次服务商快照/PITR，恢复到**第二个隔离的数据库/项目**。
- [ ] 对该恢复库跑 `RESTORED_DATABASE_URL=... bun scripts/verify-restored-database.ts`。
- [ ] 记录来源恢复时间戳、恢复耗时、迁移数量、验证器结果和清理情况；**不记录任何私有行内容**。
- [ ] 确认演练期间恢复库不会被生产/staging 的 webhook 或定时 worker 打到。

CI 会对合成的 PostgreSQL 数据跑同样的 dump/restore/验证流程。**staging 演练证明的是真实数据库服务商的备份/PITR 配置，它不替代仓库测试，仓库测试也不替代它。**

详细步骤见 [故障处理](故障处理.md)。

## 凭据轮换演练

至少选一个一次性 staging 凭据，按 [密钥轮换](密钥轮换.md) 的对应章节执行：

- [ ] 创建替换凭据。
- [ ] 按文档的重叠期或维护流程部署/切换。
- [ ] 验证依赖它的那条链路。
- [ ] 验证回滚/恢复路径，且**不复用已泄露凭据**。
- [ ] 吊销旧凭据。
- [ ] 只记录凭据用途/密钥标识和证据，**绝不记录密钥本身**。

即使实际只轮换一个凭据，也要把 Better Auth、Google、Resend、Waffo API/私钥、Waffo webhook 验签、Turnstile、cron/内部任务、数据库凭据和分析目的地的流程全部过一遍。

## 登录与反滥用

- [ ] Magic Link 会渲染 Turnstile，且在挑战完成前无法提交。
- [ ] 合法挑战放行；伪造/过期/重放的挑战被拒绝。
- [ ] action 和 hostname 不匹配会被拒绝。
- [ ] Magic Link 对邮件扫描器安全，且**只能用一次**。
- [ ] 持久化的邮箱/IP 限流跨请求生效，且**不泄露账号是否存在**。
- [ ] 开启 Google OAuth 时，state/回调/跳转行为已验证。
- [ ] 敏感页面和认证端点是 `no-store` 且 `noindex`。

## 交易、订阅与积分

开启交易时：

- [ ] 测试结账用的是 staging/test 商户和精确配置的商品 ID/价格。
- [ ] 合法签名 webhook 被接受，重复投递是幂等的。
- [ ] 非法签名**不留存**原始载荷。
- [ ] 已知成功事件不留原始载荷；瞬时/未解析留存符合配置上限。
- [ ] 多个 worker 可以并发处理/清除而不重复认领。
- [ ] 订阅的取消/恢复/宽限/终态转换已针对服务商测试环境验证。
- [ ] 退款发起和服务商结算对账已验证；**服务商结果不确定时走对账/人工复核，而不是直接改状态**。
- [ ] 一次性和订阅的积分履约都是幂等的。
- [ ] 在来源额度过期**之前**建立的预留，在过期**之后**仍能提交。
- [ ] 来源额度过期后的释放/陈旧过期**不会**恢复可用余额。

详见 [交易与积分](交易与积分.md)。

## 定时任务、指标、告警与死信

- [ ] Vercel 只调度配置好的 `/api/internal/jobs/{commerce,reconcile,credit-expiry,account-deletion}`。
- [ ] 缺失/错误的 Bearer 凭据返回 `401`；**密钥绝不通过 query string 接受**。
- [ ] 批量和运行时上界在任务行为/日志中可见。
- [ ] 并发 worker 不会重复认领带租约的工作。
- [ ] 结构化指标中**不含**任何用户/订单/支付/会话标识。
- [ ] 触发并实际收到测试告警：死信产生、Magic Link 激增、非法 webhook 签名激增、对账不一致、任务陈旧/积压、服务商重复失败。
- [ ] `scripts/inspect-dead-letters.ts` 只显示脱敏元数据。
- [ ] 在 staging 造一个合成死信，用 `scripts/retry-dead-letter.ts` 重新入队，要求 environment/id/reason/confirm 四个参数，并留下不可变审计事件。

## SEO、隐私与性能

- [ ] 用**生产模式**做浏览器验证，canonical 是预期来源。**test 模式的 `noindex` 行为不能当生产证据。**
- [ ] 公开可索引页面输出正确的 canonical/title/description/robots，且在 sitemap 中的归属符合预期。
- [ ] 私有/法律/系统路由的索引规则与路由注册表一致。
- [ ] 脚本 CSP **不依赖 `unsafe-inline`**；Turnstile/服务商来源是显式列出的。
- [ ] 产品的必要功能不依赖同意：拒绝会被持久化、设置可重新打开、同意可撤回，撤回后分析停止。
- [ ] 分析事件载荷只含白名单里的非敏感属性。
- [ ] 服务商激活之后，真实页面的性能预算仍在仓库门禁内。
- [ ] 生产开启 IndexNow 时：`GET /indexnow-key.txt` 从 canonical 主机返回配置的密钥纯文本。
- [ ] 缺失或错误的 Bearer 凭据无法调用 `POST /api/internal/seo/indexnow`。
- [ ] 只提交**真正近期发生变化**的生产 URL（新增、更新、删除、移动或重定向），绝不提交 staging 站或未变化的整份 sitemap。
- [ ] 记录变化的 canonical URL、提交时间和服务商接受的 HTTP 状态（`200` 或 `202`），**不记录 `CRON_SECRET` 或其它私有凭据**。
- [ ] `/sitemap.xml` 保持提交/可访问，作为完整 URL 清单。**IndexNow 是增量变更通知，不是 sitemap 的替代品。**

## 发布决策

仓库完成和上线激活是三个不同的状态：

- **仓库完成**：所有代码、测试、运维手册、干净安装证明、恢复证明和 CI 门禁在不需要私有生产资源的前提下全部通过。
- **staging 已激活**：上面每一条适用的外部资源都有真实证据。
- **生产就绪**：staging 激活完成，生产的法律/域名/服务商/搜索/告警资源已确认，生产模式的 SEO/安全检查针对目标来源通过，且回滚/恢复的归属人已指派。

**在外部激活完成之前，把 PR/发布记录里的阻塞项写清楚，而不是靠削弱配置或用占位符替代缺失的事实来"通过"。**
